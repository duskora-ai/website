How a ticket becomes shipped code

  1. Plan An agent reads the ticket and your codebase, then writes a plan before any code changes.
  2. Build It implements the change on a branch, runs your CI checks and opens a pull request.
  3. Review A separate agent reviews the diff and sends it back if it isn't right.
  4. QA Each acceptance criterion is tested, with screenshots attached as evidence.
  5. Deploy After your approval, the change is merged and followed through to production.

What the beta includes
