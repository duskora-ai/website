How budgets work in Duskora: predictable spend for AI agents

"What will the agents cost us?" is the first question most teams ask. In Duskora, the answer is a number you set. Every ticket has a budget, every project can have a monthly cap, and every agent run shows exactly what it cost.

AI agents do real work, and real work costs money. Each time an agent plans, builds, reviews or tests a ticket, it calls a model, and the model vendor charges for it. That's fine as long as you know where the money goes and nothing runs away from you.

Duskora is built so you never have to guess. This post walks through the controls that keep spend predictable, and where to find each one.

Where the money goes

Duskora runs its agents on your own model keys. Add an Anthropic or OpenAI API key in your organization's settings and the agents use it for every run. The vendor bills model usage to you, at your rates, separately from your Duskora subscription. Duskora doesn't resell or mark up model usage.

Every agent run is recorded with the agent, the model it used and what it cost. Open any ticket and the activity log shows the full trail, with the running total in the Agent spend card beside it.

1. A budget on every ticket

Every ticket gets a budget: the most its agents may spend on it, across every run. The default is $30 per ticket, and you can change the default for each project in Settings → Budgets.

Some tickets need more room than others. On any ticket, an admin can click Change on the Agent spend card and give that ticket its own budget, higher or lower. The card then marks it as custom, so it's clear the ticket isn't on the default.

When a ticket's budget runs out, no new agent runs start on it. The ticket tells you why, and once you raise its budget you can retry.

2. A monthly cap, with alerts

On top of the per-ticket budget, each project can have a monthly cap: the most all of its agents may spend in a calendar month. It's optional, and you set it in the same Settings → Budgets card, which also shows this month's spend against the cap.

As spend climbs, Duskora posts an alert to the project's Slack channel at 50%, 80% and 100% of the cap. Each alert fires once a month and links straight to the budget settings, so the right people see it with time to act.

At the cap, new agent runs pause until the budget is raised. No surprise bills at the end of the month.

No run can overshoot

Budgets aren't only checked between runs. When an agent starts, Duskora gives that run its own spending limit: the smaller of what's left on the ticket and what's left in the month. A single long run can't blow through the budget halfway.

If there's too little left for a useful run (under $0.50), the run doesn't start, and the ticket says which budget needs raising.

3. Pick the model for each agent

The biggest lever on cost is the model. In Agents, you choose the model for each stage from the vendors you have keys for. Bigger models are more capable but slower and cost more, so you can save them for the stages that need them.

The ticket above used a small, fast model to plan for $0.07, and stronger models to build, review and test. If you've added both an Anthropic and an OpenAI key, you can mix them too, for example reviewing with a different vendor's model from the one that built the change.

See where it went

Each project has a Spend page for the month. It shows:

  • The month against your capTotal spend so far, with a meter against the monthly budget if you've set one.
  • Spend by dayA daily chart, so a busy day stands out.
  • By agent role and by modelWhich stages and which models the money went on.
  • Top ticketsThe tickets that cost the most this month, one click from their trail.

Who can change budgets

Anyone in the organization can see spend. Only owners and admins can change the default ticket budget, the monthly cap or a single ticket's budget, so the limits stay where you set them.

A sensible way to start

  1. Keep the $30 defaultIt's plenty for most well-scoped tickets. Watch a few through and adjust from what you see.
  2. Set a monthly capPick the most you'd be comfortable spending in a month, and let the alerts tell you when you're getting close.
  3. Send alerts to a channel someone readsRoute the project's Slack notifications to the channel where the team already talks about the work.
  4. Match models to stagesStart with a smaller model for planning and see whether it's good enough before upgrading.
  5. Set a limit with your vendor tooDuskora's budgets limit what its agents spend, but the key is yours. A spend limit in your Anthropic or OpenAI console is a sensible backstop.
